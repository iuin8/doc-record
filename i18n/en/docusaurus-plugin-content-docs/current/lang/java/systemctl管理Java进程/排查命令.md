## Connect OM process with support-service

- Firm support-service run UID (zom down)

```bash
#1. View support-service systemd configuration, confirmation running user
systemctl cat support-service. ervice | grep -i "User="
# Example output：User=1000 (indicating that service works with UID 1000)

# 2. If no User=s in configuration, default is run root (UID 0). Verify
# through re-time processes to view running UID
ps aux | grep support-service | grep -v grep | awk '{print "PID:" $2, "UID:", $1" Process name: "$11}'
# Example Output：PID:919824 UID:1000 Process Name:/usr/bin/java (matching UID 1000 of OOM log)
```

- History PID (fact matching) by OOOM Time Point, enquiry support-service

```bash
# Syntax：journalctl -u service name -- since "OM Time" --until "OM Time+5 minutes" | grep "Main process ID"
# For example OM 03:41 on September 4, 03:41 PID
journalctl -u support-service for this time. ervice --since "2025-09-04 03:40:00" --untill "2025-09-04 03:45:00" | grep -i "Main process ID"
```

- Combine memory feature with second validity (avoid misjudgment)

```bash
# View memory of current support-service (compared to OM log total-vm/anon-rss)
ps aux | grep -v grep | awk '{print "PID:" $2, "Virtual memory:", $5, physical memory: "$6}'
# Example output：PID:919824 Virtual memory:6618000kB Physical memory:1031000kB
```

## How can you extra：avoid support-service being killed by OOOV?

- Add memory limit

```bash
[Service]
Memory Limit=2G # Limit=2G # Limit max as 2GB (can be mismatched)
MemoryHigh=1.5G # Memory Trash if memory exceeds 1.5GB
```

```bash
# Restart service：
systemctl daemon-load && systemctl restart support-service
```

- Optimize App Memory Configuration

Adjust Java JVM parameters (e.g. -Xms512m -Xmx1500m), avoid memory overflow：
add JVM points to service startup script, or configure them via JAVA_OPTS environment variables.

```bash
# Example：add JVM parameter
JAVA_OPTS="-Xms512m -Xmx1500m" in service startup script.
```

- Check System Total Memory

Use `free h` to see if the system has sufficient memory, consider extending the server memory if you have a regular OOM.
