# Jedis, dependent on spring-data-redis, added \`<optional>true<optional>to require developer active explicit dependency.

In Spring Data Redis `jedis` relies on labelled `<optional>true</optional>`because Spring Data Redis an umbrella that supports multi-Redis driven, including Jedis and Lettuce etc.This means that Spring Data Redis itself does not oblige projects to use Jedis, but rather allows developers to choose which client to use according to their needs.Therefore, the `jedis` dependency is set to be optional, so developers need to explicitly introduce this dependency only if they need to use the Jedis client.
With respect to the specific role of `<optional>true</optional>`, when this is marked as `true`, Maven builds the project, if other dependencies already provide implementation of this dependence, then this dependency will not be added to classpath.This has the advantage of reducing project dependence on conflict and volume, especially when another Redis client (e.g. Lettuce) is already used by default in the project.
In some cases, if you explicitly refer to the Jedis class or method in your code, even if it is optional, Maven will rely on it as compilation and running.So, if you really need to use Jedis in the project, you need to explicitly introduce this dependency and mark it as optional (i.e. set up `<optional>false</optional>`) to ensure that the project is correctly built and run using the Jedis client.
Overall, `<optional>true</optional>` is marked to provide flexibility to allow developers to decide whether to introduce Jedis dependency based on their needs and project configuration.The correct way to introduce the Jedis dependency depends on whether you need to use the Jedis client in your project, and whether you have selected other Redis clients (e.g. Lettuce).
